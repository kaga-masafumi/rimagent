# 人間主導モード（assist）

Codexのチャットから直接操作する場合は、[rimworld-director](../skills/rimworld-director/SKILL.md)を利用できます。
この方式ではAssistを起動せず、CodexがRimBridgeを直接呼びます。

人間が結果と次の行動を決め、LLMが自然言語をゲーム操作に変換するモードです。
既存の `rimagent play` とは別のコントローラーを使います。
待機中やゲーム進行中にはLLMを呼びません。自動思考・自己改善・watchdog・自動Gitコミット・次ゲーム開始もありません。

## Windowsで起動する

1. [Windows導入手順](WINDOWS_LLM.md)に従い、RimBridgeを導入する。Stewardは任意。
2. `config.local.yaml` でプロバイダーを選び、OpenAIならリポジトリ直下の `.env` に `OPENAI_API_KEY` を設定する。
3. RimWorldを起動して、人間がセーブを読み込む。設定の **Run in background** を有効にする。
4. リポジトリ直下のPowerShellで実行する。

```powershell
& ./script/start-assist.ps1
```

画面は既定で `http://127.0.0.1:8770`。ゲームを停止し、指示を待ちます。
既存のplay / assistは先に終了してください。同じリポジトリの両モードは同時起動できません。

CLIからは `cd agent` の後、`uv run --frozen rimagent assist`。
ブラウザーを開かない場合は `--no-browser`（スクリプトでは `-NoBrowser`）。

## 操作の流れ

- 「3人分のベッドを木材で拠点内に用意して」などを入力し、「指示を送る」。送信時にゲームを停止します。
- LLMが必要な状態・ID・仕様を調べ、ゲーム指示を設定します。
- 正常に設定できたら結果を報告し、ゲームを自動再開します。初期速度は1倍速。
- キャラの作業と結果を人間が観察します。建築予定の配置は建物の完成を意味しません。
- 「停止して指示」を押して次の指示を入力します。以降の再開には人間が選んだ速度を使います。
- 質問が出たら同じ入力欄から回答します。同じ指示の上限を引き継ぎます。

部分失敗・上限・接続異常・予算停止は自動再開しません。操作履歴を確認して追加指示するか、必要なら人間が「再開」を押してください。
タイムアウトした変更操作は結果不明です。ゲーム内で確認してから追加指示してください。自動再送はしません。
同じセーブの再読込やゲーム切替を含め、セーブを人間が変更するときはassistを終了し、読込後に起動し直してください。

## 継続的な自動処理

起動時にStewardの仕事優先度・在庫・standing ordersを無効化します。
以前に作成された建築予定、製造指示、作業指定は消しません。

明示的に自動化を指示する場合だけ、入力欄の「今回の指示で許可する継続的な自動処理」を選択してください。
選択は有効化の許可であり、それだけではゲーム設定は変更されません。
Standing ordersは個別のIDだけを有効化します。在庫処理は既存ジョブIDで対象を指定し、対象外を停止します。
将来追加される既定の簡単な食事製造ジョブを限定できない場合は、在庫モジュールを有効化せず、通常の製造・作業指示を使います。
Stewardの状態は専用画面で確認できます。再起動すると再び無効化します。

## 上限と費用

1指示でAPI要求20回、操作40回が既定上限です。Qwenの空回答再試行もAPI回数に含めます。
状態の取得・画像取得も操作枠を使い、`ui.build_many` は個別の建築操作数を数えます。
上限に達しても追加の要約APIは呼びません。画面の履歴に実行済み内容を残し、ゲーム停止を維持します。

```yaml
assist:
  max_api_calls: 20
  max_operations: 40
```

日次$1・月次$10（Asia/Tokyo）は既存の `budget` 設定と `runs/usage.sqlite3` を共有します。
単価未設定のQwenモデルは料金未設定と表示し、無料とは扱いません。
予算停止は「再開」で解除しません。停止後に既存のusage照合・明示解除手順を使ってください。
API回数は送信ゲートを通った試行数なので、予算予約で拒否された試行が含まれる場合があります。

## 中断・終了

「今回の指示を中断」は、新しいAPIとゲーム操作を止め、ゲーム停止を要求します。
実行済みのゲーム操作は戻しません。既に通信中のAPIの使用量は返答後に記録します。
処理中の変更RPCが終わるまで停止操作が待つ場合があります。

終了は画面の「終了」、または次のスクリプトです。

```powershell
& ./script/stop.ps1
# 要求待ちで終了しない場合
& ./script/stop.ps1 -Force
```

RimWorldは閉じません。ゲーム停止に失敗した場合はゲーム画面で手動停止してください。
強制終了で課金結果が不明になった場合は、再起動前に使用量を照合します。

## ローカルAPIと記録

- `POST /api/commands`: `text`, 一意の`request_id`, 任意の`permissions`、質問回答時の`answer_to`。
- `POST /api/control`: `action` は `pause`, `resume`, `cancel`, `kill`。再開時の`speed`は1・2・3。
- `GET /api/state`: 指示の状態・操作履歴・ゲーム状態・Steward状態。
- `GET /api/usage`: 共通台帳と指示ごとの推定費用。
- `GET /screenshot.png`: 人間向け画像。LLM送信なし。

指示履歴は `runs/assist-commands.jsonl` に保存します。再起動で指示を再実行しません。
重複request_idの送信も再実行しません。新しい指示には新しいIDを使ってください。
待機中の画面更新はゲーム状態と台帳の読み取りだけです。

## 検証

自動テストはAPIとゲーム接続を模擬し、課金APIを呼びません。
実機では別の検証用コロニーで、使用禁止解除・ベッド建築予定・製造指示から確認してください。
操作結果、停止・再開、待機中に台帳が増えないことを照合します。
RimBridge／StewardのC#ソースは変更していません。
