## 原因と改善

1. **指示受付と効果を混同した。** `ui.attack` は `AttackStatic` を設定し、`endIfCantShootTargetFromCurPos=false`。壁で撃てなくても攻撃中のまま留まる。自動で回り込む操作ではない。射線と射程を確かめ、傷・体力で効果を検証する。
2. **移動・装備・攻撃が互いに中断した。** 装備変更はequipmentで確認し、未完了なら次の命令を成功後の操作として扱わない。`ui.goto(draft=false)`は既存の徴兵を解除しないため、`ui.draft(false)`を明示する。
3. **防衛準備が遅かった。** 医療担当のMilaだけが射撃可能な状態で、装備を屋外へ取りに行く判断をした。平時に武器・防具・ペット退避範囲・実際の出入口を確認する。射撃位置までの経路を準備し、非戦闘員とペットを先に守る。
4. **接近時間と退避時間を比較しなかった。** 壁を回り込む間に敵が接近した。Moving容量と実測した位置変化から退避余裕を判断する。より遅い人物が開けた場所で追われ始めてから逃げる作戦は、今回の局面では距離を維持できなかった。
5. **読み取りと説明が過剰だった。** 全状態の反復で出力が切れ、重要な差分を見落としやすくなった。今回の局面では新しいマップ画像を見直す手順も抜けた。位置と壁の文字グリッドだけで射線を推測したことも判断の不確実性を増やした。緊急時は必要な画像を一度確認し、位置・job・装備・新しい傷をまとめて絞り、重要な判断変更を中心に報告する。停止自体は安全のため維持する。
6. **監視目標を代用した。** 完成したバッテリー目標は直ちにcompletedとなり、その後MealSimple1000個を研究待ちの代用にした。実際の目標との対応が不明確になる。今後は表現可能な実目標を使い、研究目標が未対応であることを明示する。今回その目標機能の拡張はしていない。

## 実装した操作権

対象はCodex直接プレイ用スキルと補助スクリプト。Runner／Assist、RimBridgeのC#やゲーム操作RPCは変更しない。

- ミッション開始時に担当を一度確認し、既定はCodex。人間を選ぶと戦闘のみ人間に委任する。
- `mission start --combat-owner codex|human` で選択を保存する。未設定の既存利用もCodex。
- 人間担当時の敵・新しい襲撃／暴走通知でゲームを停止し、`human_handoff`。既知の敵を承認していても引き継ぐ。
- 引き継ぎ後はすべてのCodex変更操作とwaitを拒否する。通知閉じや速度変更も割り込みになるため拒否。読み取りは許可する。状態は `runs/director-mission.json` に永続化し、プロセス再起動やmission startで勝手に解除しない。
- 人間が途中で「戦闘は俺に任せて」と言った場合は `mission handoff`。一度だけ停止し、既存命令は維持して報告する。再度handoffを呼んでも人間のゲームを止めない。
- 進行中のwaitには要求ファイルで中断を伝え、次のポーリングで停止する。pendingは停止完了ではない。paused確認後に人間の操作開始を案内する。
- 人間がゲームを停止して「終わった、続けて」と言ったら `mission return`。敵が残っていれば拒否し、明示的にCodexへ戦闘を戻す場合だけ `--combat-owner codex` を付ける。復帰コマンド自体はゲームを再開しない。
- 戦闘終了後に通常の火事・治療・設備復旧・研究へ戻る。人間担当の選択は次の戦闘でも維持する。

この制限は当スキルの補助スクリプトに適用される。他の独立したHTTPクライアントや人間のゲームUIは制限しない。人間操作中にはCodexの監視を起動しない運用を合わせて守る。実機での人間への引き継ぎ試験は未実施。
